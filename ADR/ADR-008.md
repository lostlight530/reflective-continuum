# Task wrappers operate only on explicit inputs and outputs

- Decision date: 2026-08-05
- Review calibration: 2026-08-24
- Status: Accepted
- Implementation anchor: `CODE/tasks/**`

## Status

Accepted for the bounded reference implementation; broader system claims remain out of scope.

## Context

The current task modules are bounded wrappers around local repository functions. They are not the authority for periodic research history and do not silently convert task output into durable research truth.

## Decision

Current task semantics are defined by their explicit inputs:

- `cortex_selfcheck.py` — database path, optional output path
- `semantic_drift_audit.py` — database path, caller queries, from/to versions, optional output path
- `convergence_drill.py` — iteration count over one fixed local fixture
- `insight_morpher.py` — caller-provided JSON signal file; current CLI uses a fresh default in-memory store

Where implemented, task results are emitted as structured JSON on stdout; only tasks with an explicit output option write to the caller-supplied path.

`RESEARCH/**` artifacts remain separate point-in-time research records.

## Consequences

Callers receive an inspectable local contract but remain responsible for deployment, authority, persistence, and claims outside the named implementation surface.

## Verification

Verification requires a named repository path, revision, fixture or store identity, command, environment, exit code, and retained failures. Documentary review alone is not runtime or semantic validation.

## Evidence boundary

- selfcheck result applies to the database connection it opened
- drift audit applies to the selected versions/queries and FTS5 lexical ranking
- convergence drill demonstrates repeatability of its fixed local fixture only
- insight-morpher acceptance is local ingestion/validation evidence only

Task success does not establish source truth, durable cross-task memory, semantic alignment, or global convergence.
