# State continuity requires explicit identity evidence

- Decision date: 2026-08-24
- Status: Accepted
- Scope: database state, graph snapshots, task history, transitions, and periodic research evidence

## Context

August 2026 exposed several different continuity questions:

- whether R1 write evidence and R2 read evidence refer to the same database
- whether repeated snapshot digests represent one durable object or rebuilt identical fixtures
- whether a bare SQLite `:memory:` store can be linked across independent connections/tasks
- whether a transition was synthetic/test or operational
- whether a later reconciliation file is an original runtime artifact
- whether a currently present file was visible to an earlier aggregation snapshot

The 2026-08-06 R2 case is the canonical historical example: a path exists now, but it is a later reconciliation record and the original runtime result remains unknown.

## Decision

A continuity claim names both the object and the evidence linking observations of that object.

Relevant identities can include:

- filesystem/URI database identity
- connection/run/task identity
- graph version/schema/revision
- snapshot digest **plus** store/fixture identity
- transition/event origin
- artifact logical date plus generation/delivery history
- aggregation snapshot identity

When the link is absent, use an explicit unresolved state:

- `PERSISTENCE_LINK_NOT_VERIFIED`
- `TRANSITION_ORIGIN_NOT_COMPUTED`
- `UNRESOLVED_DELIVERY_HISTORY`
- `HISTORICAL_RUNTIME_UNKNOWN`

## `:memory:` rule

A bare SQLite `:memory:` database is connection-local. Its content cannot be used as evidence of cross-task, cross-process, or cross-day continuity without a separately evidenced shared-store mechanism.

## Digest rule

A repeated snapshot digest can establish repeatability/identity of represented content under the same serialization contract. By itself it does not prove persistence through time.

`convergence_drill.py` is the canonical implementation example: each iteration creates a fresh `GraphDB()` and rebuilds the same fixed fixture, so one repeated digest is `RUN_LOCAL_REPEATABILITY_ONLY`, not durable memory.

## Historical rule

Current path presence does not rewrite an earlier execution state. A later successful read does not prove an unobserved persistence interval. Weekly/Monthly aggregation preserves unresolved continuity unless new identity evidence resolves it.

## Evidence boundary

This ADR governs interpretation of state continuity. It does not create a durable storage service or a shared-memory mechanism.
