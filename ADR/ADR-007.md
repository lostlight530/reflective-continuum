# Prose is not runtime policy

- Decision date: 2026-08-05
- Scope: reflective-continuum storage, analysis, validation, tasks, and verification

## Status

Accepted.

- Supersedes named ADR: `NONE`
- Historical correction scope: replaces earlier behavior in which documentation prose could influence executable policy through regex extraction; no predecessor file is asserted

## Context

Regex extraction of constants from bilingual ADR prose was brittle and allowed documentation edits to alter execution.

## Decision

RuleConfig is the sole executable policy. RuleEngine retains adr_dir only for source compatibility and never parses ADRs. Python checks use AST and interpreter stdlib inventory.

## Consequences

Config changes are visible in code/tests; prose cannot silently change behavior.

## Verification

Validator tests assert explicit constants, empty parsed constraints, and AST import decisions. Passing supports only the tested revision/configuration.

## Exceptions

An exception requires owner, expiry, affected failure/threat model, compensating control, test, migration when relevant, and rollback in a reviewed pull request.
