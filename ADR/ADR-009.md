# Evaluation and claim scope

- Decision date: 2026-08-05
- Review calibration: 2026-08-24
- Scope: reflective-continuum storage, analysis, validation, tasks, and evidence claims

## Status

Accepted.

- Supersedes named ADR: `NONE`
- Historical correction scope: replaces earlier prose that promoted repeatability/selfcheck evidence into deterministic convergence, alignment, or other global capability claims; no predecessor file is asserted

## Context

Repeatable hashes and successful selfchecks were previously described as deterministic convergence or alignment. The implemented repository exposes several narrower evidence surfaces that must remain separate.

## Decision

Every material result identifies the implementation/evidence surface relevant to the claim and preserves its limitations.

Keep separate:

- database initialization/integrity
- transaction success or rollback
- snapshot identity/repeatability
- lexical search-result change
- structural graph delta
- PageRank/rank delta
- graph-derived entropy
- rule-engine acceptance
- source/claim support
- durable persistence continuity
- historical task execution state

A higher-level report preserves Daily errors, failures, rejected signals, `NOT_COMPUTED`, and unresolved state unless new evidence directly resolves that dimension.

A Weekly execution snapshot is not evidence that every Daily run had the same result.

## Consequences

Claims become narrower and easier to falsify.

Successful ingestion, a stable hash, an unchanged top lexical result, or a current selfcheck cannot substitute for persistence identity, source validation, semantic truth, or historical execution evidence.

The current function named `compute_semantic_delta` reports a top-result change in FTS5 lexical search. It must not be described as a general semantic-equivalence measurement.

## Verification

Use only evidence surfaces that actually exist for the relevant revision and exact claim.

Examples:

- `snapshot_digest()` supports identity of the declared graph snapshot
- `semantic_drift_audit.py` supports its selected versions and caller-provided lexical queries
- `cortex_selfcheck.py` supports the named checks for the database connection it opened
- source/research records support only propositions traceable to their source authority and temporal provenance

A successful result supports the exact property measured, not a global system capability.

## Exceptions

An exception requires an explicit owner, affected claim/failure model, bounded compensating evidence, and correction/rollback path. Silent exceptions are invalid.
