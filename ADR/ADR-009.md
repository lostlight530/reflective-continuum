## Context

Repeatable hashes and passing selfchecks were described as deterministic convergence or alignment.

## Decision

Every result records revision/environment/fixture/query/budget and limitations. Repeatability, integrity, persistence, security, semantic validity, source support, and agent behavior are separate claims. External AI evaluations include harness and budget.

A higher-level report preserves Daily errors, failures, rejected signals, `NOT_COMPUTED`, and unresolved state unless new evidence directly resolves that dimension. A weekly execution snapshot is not evidence that every Daily run had the same result.

## Consequences

Claims are less dramatic but reproducible and falsifiable. Successful ingestion, a stable hash, or a passing current selfcheck cannot substitute for persistence identity, source validation, or historical execution evidence.

## Verification

Use only evidence surfaces that actually exist and actually ran for the relevant revision: retained commands/results, evidence baseline, reproducibility record, artifact/diff review, and other explicitly recorded checks. Unrun or absent CI/test matrices are not verification evidence.

Passing supports only the tested revision/configuration and the exact claim measured.

## Exceptions

An exception requires owner, expiry, affected failure/threat model, compensating control, evidence/test plan when applicable, migration when relevant, and rollback in a reviewed pull request.
