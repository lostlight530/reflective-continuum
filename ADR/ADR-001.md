# Standard-library runtime and explicit contracts

- Decision date: 2026-08-05
- Review calibration: 2026-08-24
- Scope: reflective-continuum storage, analysis, validation, tasks, and evidence claims

## Status

Accepted.

- Supersedes named ADR: `NONE`
- Historical correction scope: replaces earlier absolute or unverifiable repository prose about dependency minimalism and correctness; no predecessor file is asserted

## Context

A small auditable core is valuable, but “zero dependency” cannot establish correctness, persistence, or security.

## Decision

Runtime code uses the Python standard library only. Formats, data constraints, transaction behavior, and error boundaries are explicit contracts.

Python-version compatibility is revision- and evidence-specific: a version is supported only to the extent that the relevant executable behavior was actually run in that environment and the result was retained.

ADR prose is never executable configuration.

## Consequences

The dependency surface remains small, but callers still own SQLite build features and deployment controls.

Documentation must not infer compatibility or correctness from the mere presence of a test file, historical sentence, configuration file, or generated completion claim.

Standard-library-only import validation is not a sandbox and does not establish behavioral safety.

## Verification

Record or cite the evidence surface relevant to the claim being made.

Examples:

- `GraphDB` initialization can establish foreign-key/FTS5 behavior for the opened database
- `RuleEngine.verify_stdlib_only()` can establish only the import-root property it checks
- a selfcheck can establish only its named checks for the store it opened
- a snapshot digest can establish snapshot identity/repeatability for the declared fixture, not persistence through an unobserved interval

A successful result supports only the property, revision, and configuration actually observed.

## Exceptions

An exception requires an explicit owner, affected failure/threat model, bounded compensating evidence, and correction/rollback path. Silent exceptions are invalid.
