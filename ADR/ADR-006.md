# Ingestion outcome and source support are separate

- Decision date: 2026-08-05
- Review calibration: 2026-08-24
- Status: Accepted
- Implementation anchors: `CODE/tasks/insight_morpher.py`, `CODE/cortex_observer.py`

## Status

Accepted for the bounded reference implementation; broader system claims remain out of scope.

## Context

`InsightMorpher` accepts caller-provided JSON signals and passes each signal through `CortexObserver`. The resulting `accepted` field is a local validation/transaction outcome.

It is not an epistemic verdict on an external proposition.

## Decision

Keep these states independent:

- signal schema/field validity
- local observer acceptance/rejection
- database transaction result
- source identity/authority
- whether the source supports the exact proposition attributed to it
- broader research interpretation

`InsightMorpher` accepts only the declared signal fields (`id`, `content`, `edges`, optional `version`) and does not fetch or independently verify external sources.

Therefore:

`ACCEPTED != TRUE`

and:

`REJECTED_FROM_INGESTION != FALSE`.

When a cited source does not support the persisted proposition, current interpretation uses `SOURCE_CLAIM_MISMATCH` regardless of ingestion outcome.

## Consequences

Callers receive an inspectable local contract but remain responsible for deployment, authority, persistence, and claims outside the named implementation surface.

## Verification

Verification requires a named repository path, revision, fixture or store identity, command, environment, exit code, and retained failures. Documentary review alone is not runtime or semantic validation.

## Evidence boundary

An accepted signal establishes only that the current local schema/validation/transaction path accepted the supplied signal for the opened database.

It does not establish source truth, source authority, durable persistence, safety, or alignment.

The 2026-08-23 Wikipedia `AI_alignment` case remains the reference August source-to-claim mismatch.
